# Decisions — LR-20260921-DVCC-004

## Human-approved (Task Packet revision 1)

- Phase 3 implements the canonical DevVault review meanings; inventing them is prohibited.
- The review surface stays Human-operated: no ChatGPT automation, no verdict inference, no automatic
  Required Fix extraction, no AI Risk Tier decision.
- No GitHub API automation, and no IDE bridge brought forward from Phase 4.
- Existing runtime data must load without migration; `schemaVersion` is not raised lightly.
- Localization is a standing requirement: JA and EN in the same PR.
- The vault and Notion are read-only; Documentation Sync is reported, not performed.
- Final endpoint is a Draft PR. Ready, merge, release and Production are prohibited.

## Implementation decisions

| ID | Decision | Rationale |
|---|---|---|
| RW-001 | The canonical contract is discovered first and recorded verbatim in `CANONICAL_REVIEW_CONTRACT.md`, with the source path and line numbers for every concept. The implementation cites that file, not a paraphrase of it. | The Task Packet forbids inventing these meanings. A quote with a path is checkable by an independent reviewer; a summary is not. The delegated scans were read-only and their output is treated as a lead, not as the contract: the two load-bearing sources were read by this session directly. |
| RW-002 | Same-head detection reuses the Phase 2 `compareHead` contract (40-character exact, 7–39 prefix, case-insensitive, otherwise undecidable) instead of a second comparison of its own. | Task Packet §12 asks for it, and two comparisons would drift apart. The Phase 2 contract already has an independent oracle table. |
| RW-003 | *(superseded by RW-012 once the canonical set was bound to latest main.)* A second substantive review of the same head was to be shown disabled with no way to continue, because the copy read first defined no condition for continuing. | The copy read first (2026-09-03) lacks the Tier 2 Review Execution Contract, which is where the condition for re-verification is written. Kept here so the correction is visible rather than silent. |
| RW-011 | The canonical set is bound to `airesearchagl-art/obsidian-vault` **main @ `77ce41e6ff9e243ac2c8dc37ee29f5d5f4f24157`**, read read-only with the Human's explicit authorization, rather than to a local working copy. The working vault copy is 2026-09-03 and stale; the 2026-09-16 mirror is byte-identical to latest main for both load-bearing files. | `Tool_Index.md` declares these files runtime canonical and fetched from the repository's latest main, and the canonical priority puts the fresh source above a local copy. The stale copy is missing the whole section that defines evidence reuse, which is exactly what Phase 3 needs. |
| RW-012 | A second **substantive** review of the same head is offered only when the Human records a **合理的な失効理由** — an invalidation reason tied to the head, the base, the blob under review, the relevant contract or the execution environment. Without one the action stays disabled, showing the canonical rule and the two allowed paths (open the existing review, or reuse the evidence as a delta / mutable-state recheck). Nothing is ever auto-skipped, auto-closed or deleted, and no standing permission exists. | Latest main states the rule as a prohibition **with a condition**: duplicate execution without a reasonable invalidation reason is prohibited (S2 line 46), one substantive review per head is the standard (S2 lines 66, 71), and an unchanged head after a Ready transition does not require one (S4 line 58). The condition is canonical, so it is implemented as the condition — neither a free-form override nor a hard block. The reason is recorded with the round, so an independent reviewer can see why a second review was made. |
| RW-004 | `request-r<N>.md` keeps exactly the meaning it has today: it **is** Turn 1 (Stage 1 Artifact / Contract / Material Facts + Stage 2 Fresh Assessment). Turn 2 becomes a second round artifact, `followup-r<N>.md` (Stage 3 Resolution Context + Stage 4 Final Judgment), latest-wins like the request, added to the allowed review file names in both the Rust boundary and its TypeScript mirror. | Task Packet §17 forbids silently changing what an existing artifact means, and the canonical Turn 1 body is what `prompt.ts` already emits. Turn 2 cannot live inside Turn 1: the canonical rule is that the narrative is physically absent from Turn 1. A separate name per round keeps the existing latest-wins contract and the per-round file layout. |
| RW-005 | The workflow stage the Human is in is **derived**, not stored: a pure function of the round record and the Review State (request saved? follow-up saved? result captured? verdict confirmed?). The only new persisted facts are two optional round fields, `followupSavedAt` and `riskTier`. | Task Packet §16 asks for the smallest data change. Everything the stage needs is already persisted; a stored stage would be a second source of truth that can disagree with the round record. Two optional fields added the way `archivedResults` was added in Phase 1 (absent in older files, read as null) keep `schemaVersion` at 1 and let old data load untouched. |
| RW-006 | Risk Tier is a per-round value chosen by the Human (`0 | 1 | 2`, or absent = not yet decided, shown as such and never guessed). DVCC applies the canonical escalation rule as a **refusal with the reason**, not as a silent correction: when the Human has declared a Tier 2 trigger (security, privacy, credential, production, migration), a tier of 0 or 1 is refused and the canonical line is shown. | The canonical rule is that ambiguity escalates and that those five subjects are Tier 2 regardless, while the tier itself stays an explicit Human decision that a tool must not downgrade. Refusing with the rule visible honours both; deriving the tier from checkboxes would be the automatic classification §8 prohibits. |
| RW-007 | Same-head duplicate detection is a pure function over the project, the head under review and the rounds that already carry substantive evidence (a captured result or a confirmed verdict), comparing heads through the Phase 2 `compareHead` contract. Its oracle is a literal table, not a copy of the implementation's branches. | §12 and §22 ask for exactly these factors and for pure logic with an independent oracle; §27 forbids mirroring the implementation in the test. Human-written text is deliberately not part of the key. |
| RW-008 | Evidence is offered for reuse only when it is bound to the **same** head as the review about to be requested, and it is always shown with its source, its head, when it was captured or reviewed, and why it is being offered. Evidence from another head or another review is never offered, and an older conclusion is never presented as current. | The canonical rules are that evidence belongs to an exact head, that an old head's conclusion is not reused unverified, and that provenance survives with the evidence. Anything broader would be an invention. |
| RW-009 | Four language-neutral event types are added: `followup_saved`, `evidence_reused`, `risk_tier_set` and `duplicate_continued` — the last one carrying the Human's invalidation reason as its note, so a second review of the same head is never silent (RW-012). The timeline is built by grouping the existing `events.jsonl` by round; no second history store is created. | §15 asks for the existing history to be reused and for event types to stay language-neutral. A file written by this version may contain types an older build would skip — the existing contract already skips unreadable event lines with a visible count, and the data contract will say so. |
| RW-010 | Freshness stays exactly where Phase 2 put it: an independent axis. The workflow reads it to tell the Human what is stale or unobserved, and never writes a Review State from it. When the current Git state is unobserved, the workflow says so rather than treating UNKNOWN as ALIGNED. | §21 and §28, and the Phase 2 contract that Freshness never changes a Review State. |
